# 기사작성 프롬프트 회귀 샘플

공개 가능한 **재사용 프롬프트와 가상 사례 회귀 샘플**만 관리합니다. 이 저장소는 ‘나는 기자다’ 앱의 소스 코드, 운영 설정, 실제 취재자료 저장소가 아닙니다.

## 구조

| 경로 | 용도 |
| --- | --- |
| `prompts/` | 스트레이트 기사·팩트체크·질의서 형식별 지시문 |
| `fixtures/` | 프롬프트에 넣을 완전한 가상 입력과 확인 가능한 사실 |
| `expected/` | 형식별 참고 출력 예시. 문자열 일치 정답은 아님 |
| `TEST_CRITERIA.md` | 공통·형식별 합격 기준과 변경 전후 판정 절차 |
| `scripts/compare.py` | 같은 사례의 변경 전후 출력 및 참고 출력 차이 표시 |

## 변경 전후 비교

1. 비교할 프롬프트의 **변경 전 버전**과 **변경 후 버전**을 준비합니다. 바꾸지 않은 형식의 프롬프트는 동일하게 사용합니다.
2. 각 `fixtures/<형식>.json`의 `input`을 해당 프롬프트의 `{{INPUT}}` 자리에 넣습니다. 모델·설정·입력·외부 자료 접근 여부를 동일하게 고정합니다. 프롬프트 지시문이 실제 입력과 충돌하면 입력의 확인 사실을 우선합니다.
3. 두 버전의 출력을 각각 `runs/before/<형식>.md`, `runs/after/<형식>.md`에 저장합니다. 파일명은 `straight`, `factcheck`, `inquiry`입니다. 같은 조건에서 출력을 생성하되, 생성 모델을 이 저장소에 연결하거나 자동 실행하지는 않습니다.
4. `python3 scripts/compare.py --before runs/before --after runs/after`를 실행합니다. 세 사례의 변경 전후 차이와 `expected/` 참고 출력 대비 차이가 표시됩니다. **차이 유무는 합격 판정이 아닙니다.**
5. `TEST_CRITERIA.md`의 공통 기준과 사례별 기준을 두 출력에 각각 적용하고, 개선·퇴행·판정보류와 근거를 PR에 기록합니다.

## 사례 추가

같은 이름의 `prompts/<형식>.md`, `fixtures/<형식>.json`, `expected/<형식>.md`를 함께 추가하고 `TEST_CRITERIA.md`에 판정 기준을 씁니다. `fixtures`의 `input`은 프롬프트에 그대로 삽입할 수 있어야 하며, `facts`와 `must_not_infer`는 사람의 판정 근거입니다. 예시는 가상 기관·가상 숫자·가상 문서로 작성합니다.

공개 저장소입니다. 실명 취재원, 미공개 제보, 주소·연락처, 원본 문서, 고객 입력, 모델 키와 실제 생성 결과에 포함된 민감정보를 올리지 마세요. `.gitignore`는 실수 방지 보조 장치일 뿐 공개 전 검토를 대신하지 않습니다.
